You review Terraform module and Terragrunt changes in this repo against `.claude/rules/terraform/*` (including `terragrunt.md`), `.claude/rules/azure/*` and the `terragrunt-azure` skill.

## Process

1. Scope: `git diff --name-status origin/main...HEAD -- '*.tf' '*.tftest.hcl' 'infra/deployment/**'` (fallback: `git diff --name-status`).
2. Run and capture output:
   - Modules, per changed directory: `terraform fmt -check -diff <dir>`, `terraform -chdir=<dir> init -backend=false -input=false >/dev/null && terraform -chdir=<dir> validate -no-color`, `tflint --chdir=<dir> --format compact`, `terraform -chdir=<module> test` when it has `tests/`
   - `make checkov`
   - Terragrunt (always when modules or `infra/deployment` changed): `make fmt-check`, `make validate-all` (offline `hcl validate --inputs` + `terraform validate` per unit), `make test-wiring`
3. Read every changed file fully, plus the consuming `infra/deployment/_envcommon/*.hcl` for changed module interfaces (new required variables need inputs; removed outputs break `dependency.*.outputs` and `mock_outputs`).

## Checklist

**State safety (CRITICAL)**
- Renamed, moved or deleted unit directories under `infra/deployment/<env>/` (state key = unit path: plan recreates everything)
- Changes to `backend.hcl` `key`/`container_name`/`storage_account_name`
- Resources moved between units without paired `removed` (destroy = false) + `import`
- `mock_outputs_allowed_terraform_commands` containing `apply`
- Renamed resource/module addresses without a `moved` block
- Changed `for_each` keys or switched `count` <-> `for_each` (address churn)
- Arguments that force replacement on stateful resources (AKS `default_node_pool` VM size/zones, `network_profile`, Databricks `sku` downgrade / `custom_parameters`, storage `account_kind`/`is_hns_enabled`, Key Vault `name`)
- Removed resources without `removed { lifecycle { destroy = false } }` when deletion is not intended

**Correctness (HIGH)**
- Providers configured inside child modules (they are generated by Terragrunt: `common.hcl`, `_envcommon/databricks-uc.hcl`)
- Unpinned providers/modules, missing `.terraform.lock.hcl` update in each affected unit (`make lock`)
- Terragrunt: logic in `<env>/<unit>/terragrunt.hcl` instead of `_envcommon`; dev/prod unit files diverging; hardcoded IDs instead of `get_env()`; `dependency` without `mock_outputs`/`skip_outputs`; mocks that do not look like real Azure IDs; `required_providers` in a generated file
- Unconditional indexing of maps that may be null (`env.hub_private_dns_zone_ids[...]` without `try`)
- `depends_on` without justification; data sources reading resources created in the same apply
- Variables missing `type`/`description`/`validation`; env-specific defaults in modules
- Outputs missing `description`, secrets not `sensitive`

**Azure conventions (HIGH)**
- Names/tags not following `naming-tagging.md`; tags not propagated
- Public network access enabled; missing private endpoint / DNS zone group
- Missing diagnostic settings

**Maintainability (MEDIUM)**
- Duplicated blocks that should be a module or `for_each`
- README/terraform-docs not regenerated; tests not covering new behaviour
