# Terraform on Azure Patterns

Environments are composed with Terragrunt (`infra/deployment`, skill `terragrunt-azure`); this skill covers the module HCL.

## Versions (module `versions.tf`)

```hcl
terraform {
  required_version = ">= 1.9, < 2.0"
  required_providers {
    azurerm    = { source = "hashicorp/azurerm", version = "~> 5.13" }
    azapi      = { source = "Azure/azapi", version = "~> 2.2" }
    databricks = { source = "databricks/databricks", version = "~> 1.142" }
    random     = { source = "hashicorp/random", version = "~> 3.9" }
  }
}
```

Modules declare only the providers they use, with the same constraints, and never a `provider` block.

## Provider configuration (generated by Terragrunt)

`infra/deployment/common.hcl` generates `provider_azurerm_gen.tf` into every unit (`generate "provider_azurerm"`);
`_envcommon/databricks-uc.hcl` generates the aliased `databricks.account` / `databricks.workspace` providers.
Generated files hold provider blocks only; `required_providers` stays in the module (duplicates are an error).

```hcl
provider "azurerm" {
  features {
    key_vault {
      purge_soft_delete_on_destroy = false
    }
    resource_group {
      prevent_deletion_if_contains_resources = true
    }
  }
  # subscription is required (azurerm >= 4): this repo supplies it via ARM_SUBSCRIPTION_ID
  # (Makefile exports it from `az account show`; CI sets it per environment), never in code.
  storage_use_azuread = true
}

provider "azurerm" {
  alias           = "connectivity"            # hub: private DNS zones, peering
  subscription_id = var.connectivity_subscription_id
  features {}
}

provider "azapi" {}
```

A module that needs an alias declares `configuration_aliases = [azurerm.connectivity]`; its Terragrunt unit generates the aliased
provider block (Terragrunt units are root modules, so aliases are bound by name without a `providers = {}` map).

Auth: local `az login` (CLI auth is default); CI sets `ARM_USE_OIDC=true`, `ARM_CLIENT_ID`, `ARM_TENANT_ID`, `ARM_SUBSCRIPTION_ID`.

## When to use azapi

- Preview features or properties not yet in azurerm (e.g. new AKS profiles) -> `azapi_resource` / `azapi_update_resource` with a pinned `type = "Microsoft.X/y@<api-version>"`.
- Keep the azurerm resource as the owner; use `azapi_update_resource` for the missing property only, and add a `# TODO: move to azurerm when supported` comment with the provider issue link.

## Private endpoint pattern

```hcl
resource "azurerm_private_endpoint" "this" {
  name                = "pe-${var.name}"
  location            = var.location
  resource_group_name = var.resource_group_name
  subnet_id           = var.private_endpoint_subnet_id
  tags                = var.tags

  private_service_connection {
    name                           = "psc-${var.name}"
    private_connection_resource_id = azurerm_key_vault.this.id
    subresource_names              = ["vault"]
    is_manual_connection           = false
  }

  private_dns_zone_group {
    name                 = "default"
    private_dns_zone_ids = [var.private_dns_zone_ids["vault"]]
  }
}
```

Subresource names: Key Vault `vault`; Storage `blob`, `dfs`; ACR `registry`; Databricks `databricks_ui_api`, `browser_authentication`; AKS (private cluster) is managed by AKS itself.

## Diagnostic settings pattern

```hcl
data "azurerm_monitor_diagnostic_categories" "this" {
  resource_id = azurerm_key_vault.this.id
}

resource "azurerm_monitor_diagnostic_setting" "this" {
  name                       = "diag-to-law"
  target_resource_id         = azurerm_key_vault.this.id
  log_analytics_workspace_id = var.log_analytics_workspace_id

  dynamic "enabled_log" {
    for_each = data.azurerm_monitor_diagnostic_categories.this.log_category_groups
    content { category_group = enabled_log.value }
  }
  enabled_metric { category = "AllMetrics" }
}
```

## RBAC pattern

```hcl
resource "azurerm_role_assignment" "kubelet_acr_pull" {
  scope                            = var.acr_id
  role_definition_name             = "AcrPull"
  principal_id                     = azurerm_kubernetes_cluster.this.kubelet_identity[0].object_id
  principal_type                   = "ServicePrincipal"
  skip_service_principal_aad_check = true
}
```

Always set `principal_type` to avoid replication-delay failures.

## Replace-trigger pitfalls

| Resource | Forces replacement |
|----------|--------------------|
| `azurerm_kubernetes_cluster` | `default_node_pool.vm_size`/`zones` (unless `temporary_name_for_rotation`), `network_profile.*`, `dns_prefix`, `private_cluster_enabled` |
| `azurerm_kubernetes_cluster_node_pool` | `vm_size`, `zones`, `vnet_subnet_id`, `os_disk_type` |
| `azurerm_databricks_workspace` | `custom_parameters.*`, `managed_resource_group_name`, `location` |
| `azurerm_storage_account` | `account_kind`, `is_hns_enabled` (false->true allowed in place in recent versions; verify), `name` |
| `azurerm_subnet` | `address_prefixes` change when in use fails/replaces dependents |
| Any | `name`, `location`, `resource_group_name` |

Check with the `terraform` MCP server (`get provider docs`) before changing these.

## Azure Verified Modules

Prefer `Azure/avm-res-<provider>-<type>/azurerm` for well-trodden resources; pin exact versions (`version = "0.4.0"`), wrap in a thin local module when you need repo conventions (naming/tags/diagnostics).
