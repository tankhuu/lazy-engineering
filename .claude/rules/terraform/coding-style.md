# Terraform Coding Style

> Extends [ecc/common/coding-style.md](../ecc/common/coding-style.md) for HCL.

## File layout (every module and env)

| File | Contents |
|------|----------|
| `versions.tf` | `terraform { required_version, required_providers }` only |
| `providers.tf` | Provider blocks in `infra/bootstrap` only. Modules never configure providers; Terragrunt generates them (`provider_*_gen.tf`) |
| `variables.tf` | All inputs, alphabetical, each with `type` + `description` |
| `main.tf` | Resources and module calls; split by concern (`network.tf`, `identity.tf`) when > ~200 lines |
| `outputs.tf` | Outputs with `description`; mark secrets `sensitive = true` |
| `locals.tf` | Naming and tag composition |
| `README.md` | Generated by `terraform-docs` (`make docs`) |

## Naming

- snake_case for every identifier. Resource label `this` when a module creates one instance of that type, otherwise a meaningful noun (`system`, `user`, `private_endpoint`).
- Do not repeat the resource type in the label: `azurerm_subnet.aks`, not `azurerm_subnet.aks_subnet`.
- Booleans start with `enable_` / `is_`; lists and maps are plural.

## Inputs

- Use `object({...})` with `optional()` defaults instead of many loosely related scalars.
- Add `validation` blocks for anything with a constrained domain (env names, CIDRs, SKUs, regions).
- No defaults for environment-specific values (CIDRs, names, SKUs) in child modules.
- Mark secret inputs `sensitive = true`; prefer passing Key Vault references over raw values.

## Iteration and conditionals

- `for_each` over maps/sets with stable keys; `count` only for 0/1 toggles (`count = var.enable_x ? 1 : 0`).
- Never key `for_each` on values only known after apply.
- Use `dynamic` blocks sparingly; prefer explicit blocks when there are <= 2 variants.

## Dependencies

- Rely on implicit references; `depends_on` only with a comment explaining the hidden dependency (e.g. RBAC propagation before a data-plane call).
- Child modules must not configure providers; accept `providers = { ... }` from the caller for aliases.

## Refactoring

- Renames and moves use `moved {}` blocks. Adopting existing resources uses `import {}` blocks reviewed in a PR, never the `terraform import` CLI.
- Keep `moved` blocks for at least one release of every env before deleting them.

## Formatting

- `terraform fmt` is enforced by the post-edit hook, pre-commit, and CI.
- One blank line between blocks, arguments before nested blocks, `lifecycle` / `depends_on` last.
