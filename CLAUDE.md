# lazy-engineering: Azure Platform (Terragrunt + Terraform, AKS, Azure Databricks)

Claude Code project memory. Baseline harness is [ECC](https://github.com/affaan-m/ECC), installed per machine with `make ecc-sync`; this repo adds a Terragrunt/Terraform/Azure platform pack on top.

## Repository layout

Environments use the Terragrunt layout from backbase-rnd/ri-iac ADR-005 ("State Management (Terraform + Terragrunt)"); our adoption and deviations are in `docs/adr/0001-adopt-terragrunt-per-ri-iac-adr-005.md`. Record new architectural decisions as ADRs in `docs/adr/` (architecture-decision-records skill).

```
infra/
  bootstrap/            Remote state storage (plain Terraform, run once per subscription, local state)
  modules/              Reusable Terraform modules: resource-groups, network, log-analytics, key-vault, acr, aks, databricks, databricks-uc
  deployment/           Terragrunt live config (ri-iac ADR-005)
    backend.hcl         remote_state azurerm; key = <unit path>/terraform.tfstate (one state per unit)
    common.hcl          CAF names, tags, shared maps, version constraints, generated azurerm provider
    _envcommon/<unit>.hcl   module source, dependency blocks (+ mock_outputs), inputs
    <env>/env.hcl       per-env values (dev, prod)
    <env>/<unit>/terragrunt.hcl   three includes only; identical across envs
    tests/render_check.py   offline wiring assertions
.claude/
  rules/terraform/      HCL style, Terragrunt, state/backend, security, testing
  rules/azure/          Naming/tagging, identity, networking
  agents/               terraform-*, aks-platform-engineer, databricks-platform-engineer, azure-security-reviewer
  commands/             /tf-plan, /tf-review, /tf-module-new, /tf-drift, /aks-check, /dbx-check
  skills/               terragrunt-azure, terraform-azure-patterns, aks-terraform, databricks-terraform, azure-landing-zone
  hooks-platform/       Guard + post-edit hooks referenced by .claude/settings.json (+ test_guard_bash.py)
  rules/ecc, ...        ECC-managed (gitignored, regenerated by `make ecc-sync`)
.mcp.json               terraform, azure, kubernetes, databricks, context7 MCP servers
.github/workflows/      PR: fmt/validate/tflint/checkov/test + `terragrunt run --all plan`. main: `run --all apply` behind environment approval
```

## Hard rules

- NEVER run `terraform apply`, `terraform destroy`, `terraform state rm|mv|push`, `terraform import` (CLI), `terraform force-unlock`, `az ... delete`, or `kubectl delete|apply` from a local session. Changes reach Azure only through PR + CI. The PreToolUse hook enforces this.
- The same applies to every Terragrunt form: `terragrunt apply|destroy|import|force-unlock|state ...`, `terragrunt run [--all] [--] apply|destroy`, `run-all`, `apply-all`, `destroy-all`, `backend bootstrap|delete|migrate`, `--backend-bootstrap`, and `exec -- <mutating cmd>`. `run --all apply` auto-approves.
- NEVER read or print `*.tfstate`, `*.tfplan` binaries (also inside `.terragrunt-cache/`), `.env`, or Key Vault secret values. Use `terraform show -json` / `--json-out-dir` plan JSON only to summarise changes.
- NEVER hardcode secrets, subscription IDs, tenant IDs, or object IDs in `.tf` or `.hcl` files. Pass them through variables, `data` sources, `get_env()` or CI environment. (Deliberate deviation from ri-iac, whose `common.hcl` hardcodes them.)
- Pin every provider and module version, plus Terraform/Terragrunt versions. Never upgrade a provider major version in the same PR as functional changes.
- Treat any plan that destroys or replaces a stateful resource (AKS cluster, Databricks workspace, storage account, Key Vault, VNet/subnet) as a blocker until the user confirms; prefer `moved`/`import` blocks. Renaming or moving a Terragrunt unit directory changes its state key and counts as such a change.

## Workflow

1. `/plan` (ECC) or `terraform-architect` agent for any change that touches more than one module or unit.
2. Implement in `infra/modules/*` first (with tests), then wire it in `infra/deployment/_envcommon/<unit>.hcl` and values in `infra/deployment/<env>/env.hcl` (skill: `terragrunt-azure`).
3. Post-edit hook runs `terraform fmt` + `tflint` on `.tf`, and `terragrunt hcl fmt` (+ `hcl validate --inputs` for unit files) on `infra/deployment/**/*.hcl`.
4. `/tf-plan <env> [unit]` - fmt, offline validate, tflint, checkov, tests, `terragrunt run --all plan`, and a risk summary from `terraform-plan-analyzer`.
5. `/tf-review` before opening the PR; `azure-security-reviewer` for anything touching identity, network, or data.
6. `/pr` (ECC) to open the PR. CI posts the per-unit plan summary; apply happens after merge with environment approval.

## Conventions

- Terraform `>= 1.9` (CI 1.11.1), Terragrunt `>= 1.1, < 2` (CI 1.1.6), `azurerm ~> 5.13`, `databricks ~> 1.142` (`azapi ~> 2.x` only when azurerm lacks a feature). Provider versions live in each module's `versions.tf`; every unit and `infra/bootstrap` commit a `.terraform.lock.hcl` for linux_amd64 + darwin (`make lock`). CI inits with `-lockfile=readonly`.
- azurerm 5.x schema: `service_endpoint {}` blocks on subnets, string `public_network_access` on storage, `enabled_log`/`enabled_metric` on diagnostics, `storage_account_id` on containers, required `rbac_authorization_enabled` on Key Vault, required `node_provisioning_profile` on AKS. Check the schema with the terraform MCP server before guessing.
- Auth: `az login` locally (`ARM_USE_CLI=true`), OIDC (`ARM_USE_OIDC=true`) in CI. No client secrets. IDs come from env: `ARM_SUBSCRIPTION_ID`, `ARM_TENANT_ID`, `DATABRICKS_ACCOUNT_ID`, `DATABRICKS_METASTORE_ID`, `TFSTATE_SUBSCRIPTION_ID|RESOURCE_GROUP|STORAGE_ACCOUNT` (the Makefile exports the first two from `az account show`).
- Offline mode: `PLATFORM_OFFLINE=true` makes dependencies return `mock_outputs` and IDs fall back to placeholders; used by `make validate`, `make test`, pre-commit and the CI static job. Mocks are allowed for the read-only commands in `common.hcl` `mock_commands` (init, validate, plan, providers, show) only, never `apply`/`destroy` (asserted by `make test-wiring`).
- Naming follows CAF abbreviations: `<abbr>-<workload>-<env>-<region>-<nn>` (see `.claude/rules/azure/naming-tagging.md`). Names are composed in `infra/deployment/common.hcl`; modules never invent names.
- Required tags: `environment`, `owner`, `cost_center`, `managed_by=terraform`, `repo`, `workload` (from `common.hcl`).
- `infra/deployment/dev` and `infra/deployment/prod` have identical unit files; only `env.hcl` and lock files differ (`diff -r infra/deployment/dev infra/deployment/prod`).
- Run commands from the repo root through `make` (`make plan ENV=dev [UNIT=aks]`, `make validate ENV=dev`, `make lint`, `make test`, `make graph`, `make output ENV=dev UNIT=aks`).
